# 学生管理系统（学习演示项目）

中文网页版学生管理系统：学生档案、班级管理、科目管理、成绩管理，支持组合搜索与筛选，数据持久化到本地 SQLite 文件。单进程本地运行，无外部服务依赖。

- 对应任务：Multica 项目「学生管理系统」LQB-14（首版开发子任务 LQB-17，测试 LQB-18）。
- 技术栈：Node.js 24 + TypeScript + Express 5 + EJS 服务端模板 + 原生 CSS + Node 内置 `node:sqlite`（`DatabaseSync`）。
- 设计依据：`docs/architecture.md`（架构方案 ADR-001）与 `docs/ui-design-spec.md`（界面与交互设计规范）；验收对照见 `docs/acceptance-checklist.md`。

## 功能范围（首版）

| 模块 | 能力 |
| --- | --- |
| 学生档案 | 新增 / 编辑 / 查看详情 / 删除；学号唯一、自动转大写并保留前导零；可分配班级或“未分班”；删除学生同步删除其成绩（二次确认） |
| 班级管理 | 新增 / 重命名 / 删除；实时展示在读人数；班级内仍有学生时禁止删除（HTTP 409） |
| 科目管理 | 新增 / 重命名 / 删除；已有关联成绩的科目禁止删除（HTTP 409） |
| 成绩管理 | 录入 / 编辑 / 删除；0–100 且最多一位小数；每位学生每科唯一，重复录入给出编辑直达链接 |
| 查询与分页 | 学生按学号 / 姓名关键字 + 班级（含“未分班”）组合筛选；成绩按学生、班级、科目组合筛选；翻页保留查询参数；区分“暂无数据”和“未搜索到匹配项” |

不含：登录与角色权限、学期 / 考试多次成绩、真实学生数据导入、任何部署动作。

## 运行要求

- Node.js 24.x（`package.json` 中 `engines` 限定 `>=24 <25`）。本项目使用 Node 内置 `node:sqlite` 模块，无需安装 SQLite 或原生扩展；在 Node 22 上运行可能不可用或需要额外开关，请直接使用 Node 24。
- npm 10+（随 Node 24 提供）。无数据库服务、无前端构建工具。

## 安装与启动

```bash
# 1. 安装依赖（锁定版本，使用 package-lock.json）
npm ci

# 2. 初始化数据库（创建 data/student-management.sqlite 并应用迁移；可重复执行）
npm run db:migrate

# 3. 可选：写入合成示例数据（仅在空库写入，不覆盖已有录入）
npm run db:seed

# 4. 编译 TypeScript 并启动服务
npm run build
npm start
```

启动后终端会打印访问地址，默认 <http://127.0.0.1:3000>（仅监听本机）。浏览器打开即可使用；根路径 `/` 会跳转到学生档案列表。

其它命令：

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 开发模式：`tsc --watch` + `node --watch`，改动自动重编译并重启服务（Ctrl+C 一次同时停止两者） |
| `npm run build` | 将 `src/`、`tests/` 编译到 `dist/` |
| `npm start` | 以编译产物启动服务（启动时自动执行迁移） |
| `npm test` | 编译后运行全部集成 / 单元测试（真实临时 SQLite + 真实 HTTP 端口） |
| `npm run acceptance` | 编译后启动真实服务子进程，按《演示步骤》走一遍验收走查并打印每项结果（前置：已执行 `db:seed`，全新初始化或 `--force` 重置后的库均可——脚本按名称解析班级 / 科目 ID，不依赖自增主键；默认使用当前 `DATABASE_PATH`） |
| `npm run typecheck` | 仅类型检查，不产出文件 |
| `npm run db:migrate` | 应用版本化迁移（幂等） |
| `npm run db:seed` | 空库时写入合成示例数据；重复运行跳过 |
| `npm run db:seed -- --force` | **显式重置**：清空四张表后重新写入示例数据，并重置自增序列（重置后的 ID 与全新初始化一致；会删除手工录入的数据） |

## 数据保存位置与配置

- 默认数据库文件：仓库根目录 `data/student-management.sqlite`（首次启动或 `npm run db:migrate` 时创建目录）。该目录已加入 `.gitignore`，不会提交个人数据。
- 环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DATABASE_PATH` | `<仓库根>/data/student-management.sqlite` | 指定数据库文件；相对路径按仓库根解析 |
| `HOST` | `127.0.0.1` | 监听地址，默认不对外网开放 |
| `PORT` | `3000` | 监听端口 |

示例（使用独立数据库做实验，不影响演示库）：

```bash
DATABASE_PATH=./data/demo.sqlite PORT=3100 npm start
```

## 演示步骤（使用合成数据）

1. `npm ci && npm run build && npm run db:seed && npm start`，浏览器打开 <http://127.0.0.1:3000>。
2. **学生档案**：表格可见学号 `001`–`006`（前导零原样保留），其中「演示学生06」显示灰色“未分班”徽章。搜索框输入 `001` 或 `演示学生01`，选择班级「高一(1)班」后点击“查询筛选”验证组合筛选；点击“重置条件”恢复。
3. **新增学生**：点击“+ 添加新学生”，学号填 `007`、姓名填任意合成姓名、班级留空，保存后回到列表并出现绿色成功提示 `✔ 学生档案保存成功`。再次用 `007` 新增会得到红色内联提示“学号已存在，请使用其他学号”（HTTP 422，输入被保留）。
4. **转班**：在学生列表点“编辑”，把「演示学生06」分配到「高一(2)班」并保存；再回到班级列表可以看到两个班级的人数变化。转班不会影响已录入成绩。
5. **成绩管理**：点击“+ 录入新成绩”，选择学生与科目，分数依次试 `0`、`100`、`99.5`（应成功）；再试 `100.1`、`99.55`、`-1`、空值（应分别在字段下方标红并提示“请输入 0-100 之间且最多一位小数的数值”/“该字段为必填项”）。对同一学生重复录入同一科目会得到黄色横幅“成绩记录已存在……”并附带前往编辑该成绩的链接（HTTP 409）。
6. **删除保护**：班级列表中「高一(1)班」的删除按钮显示为“删除（已锁定）”，进入确认页会看到“无法删除该班级：该班级目前共有 N 名学生……”；科目列表中已有成绩的科目同样禁止删除；空班级/无成绩科目可确认删除成功。
7. **级联删除**：在学生详情页底部“危险操作区”点击删除，确认框中会明确提示“并同步删除该学生名下的全部 N 条成绩记录”；确认后成绩一并消失，取消则无任何写入。
8. **持久化**：Ctrl+C 停止服务，再 `npm start`，重新打开页面可见之前录入的数据仍在（金额、成绩、筛选等均来自磁盘上的 SQLite 文件）。

## 测试与验证

```bash
npm test
```

测试使用 Node 内置测试运行器（`node:test`），每个用例启动真实 Express 应用与真实临时 SQLite 文件，通过 HTTP 走完整表单流程。覆盖点：

- 学号规范化（去空白、转大写、前导零）、大小写冲突 422、空字段与非法字符校验；
- 学生增删改查、转班、删除学生级联删除成绩、404 场景；
- 班级重名、班级内有学生时删除返回 409（含人数）、空班级删除成功；
- 科目重名、已有成绩的科目删除返回 409、改名成功；
- 成绩 0 / 100 / 99.5 通过，空值 / 负数 / 100.1 / 99.55 / 科学计数法拒绝；重复学生+科目返回 409 并给出编辑链接；数据库 `UNIQUE` / `CHECK` / 外键约束兜底；
- 关键字与班级（含 `classId=unassigned`）组合筛选、`%`/`_` 转义、分页保留查询参数、越界页码收敛、空列表与空结果文案区分；
- 数据在重新打开数据库文件后保留、种子数据幂等且不覆盖用户录入、事务失败回滚；
- CSRF（缺少 / 错误 token 返回 403）、GET 不修改数据、未知路由 404、用户输入 HTML 转义。

## 备份与恢复

- **备份**：正常停止服务（`Ctrl+C` 或 `kill -INT`，进程会先关闭数据库连接并合并 WAL）后，`data/` 目录只保留主库文件，直接复制 `data/student-management.sqlite` 即可，该文件已包含全部最新数据。
  - 若进程是被强制结束的（`kill -9`、崩溃或断电）而未经正常停服，目录中可能残留 `-wal` / `-shm` 文件，此时请连同这两个文件一并复制（或先正常启动再正常停止一次，让 SQLite 自动合并 WAL）：只复制主库文件可能得到过期数据，甚至提示 `no such table: students`。
- **恢复**：停止服务，用备份文件替换 `data/student-management.sqlite`（如备份中含 `-wal` / `-shm` 也一并放回），再启动服务。数据库为本地演示数据文件，不承诺跨机器自动同步。
- **重置**：`npm run db:seed -- --force` 清空并重建合成数据；或停止服务后删除数据库文件再 `npm run db:migrate && npm run db:seed`。普通启动流程不会删除任何文件。

## 目录结构

```
src/
  app.ts                 Express 应用装配（视图引擎、静态资源、CSRF、路由、错误处理）
  server.ts              进程入口（读取 HOST/PORT/DATABASE_PATH，优雅关闭）
  config.ts              项目根定位、数据库路径与端口解析、UTC 时间函数
  db/
    index.ts             连接工厂、事务封装（嵌套复用、异常回滚）
    migrations.ts        版本化迁移（schema_migrations）
    migrate.ts / seed.ts 迁移与种子 CLI，seed 内含合成示例数据
  modules/{students,classes,subjects,scores}/
    queries.ts           参数化 SQL 集中处（路由不直接写 SQL）
    service.ts           业务校验、唯一性、删除保护与事务
    routes.ts            HTTP 路由、状态码与模板渲染
  shared/
    validation.ts        纯校验函数（不依赖 Express / 模板 / 数据库）
    errors.ts            HttpError（422 / 409 / 404 / 403）
    http.ts              CSRF、分页、URL 构造
    view.ts              页面元信息、成功提示字典、时间格式化
  views/                 EJS 模板（partials + 各模块页面 + 错误页）
  public/css/style.css   Design Tokens 与组件样式（来自界面规范）
  public/js/app.js       删除二次确认弹窗与学生下拉筛选（渐进增强）
scripts/dev.mjs          开发模式双进程编排
tests/                   node:test 集成与单元测试
docs/                    架构方案、界面规范、验收对照表
data/                    运行时生成的 SQLite 文件（已 gitignore）
```

## 安全与交付边界

- 仅监听 `127.0.0.1`，不提供登录与权限体系，适合本地单用户学习演示；如需公开访问必须先重新设计认证、授权与隐私方案。
- 所有 SQL 使用参数化绑定；EJS 默认转义用户内容；表单 POST 使用双提交 Cookie 的 CSRF 校验；外键、`UNIQUE`、`CHECK` 作为最后防线。
- 仓库与示例数据全部为合成内容，未导入任何真实学生资料；未执行任何部署动作。
