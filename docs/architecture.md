## ADR-001：单体服务与 SQLite

### Status
Proposed（本次推荐方案，供阶段验收）

### Context
个人学习演示、中文网页、单用户、本地启动，需维护学生、班级、科目和成绩并持久保存。没有复杂权限、部署或真实数据要求。

### Decision
采用 Node.js 24 LTS、TypeScript、Express 5、服务端 EJS 模板与普通 CSS；SQLite 使用 Node 内置 `node:sqlite` 的 DatabaseSync，显式启用外键。单个进程同时提供网页和表单处理，使用参数化 SQL、版本化 SQL 迁移；无 ORM、前端构建框架或独立 API 服务。锁文件固定实际依赖，README 固定 Node 主版本，并说明该版本内置 SQLite 的稳定性状态。

| 备选 | 收益 | 代价与结论 |
| --- | --- | --- |
| Express + 模板 + SQLite | 单进程、关系约束、数据文件可定位，便于阅读请求到数据库的完整流程 | 页面提交后刷新；同步数据库访问阻塞进程，适合本地小规模演示；推荐 |
| React + Vite + localStorage | 无后端，部署静态页面简单 | 数据绑定浏览器来源，清缓存可丢失，关联约束全靠应用；不选 |
| React + REST + SQLite | 交互丰富、前后端独立演进 | 两套构建及接口状态管理超出当前需要；后续交互需求增长再考虑 |

### Consequences
优先 CRUD 与明确事务，不引入 DDD 聚合、消息队列、微服务或仓储接口体系。服务函数负责校验和事务；SQL 集中在各模块查询文件中，路由不直接写 SQL。若未来需公开访问或多用户，先重新设计认证、授权、并发与隐私方案，再评估 PostgreSQL 和异步访问。

## 模块与依赖

建议结构：`src/modules/{students,classes,subjects,scores}/{routes,service,queries}.ts`；`src/views/` 放中文模板和通用表单错误；`src/db/` 放连接、迁移与事务；`src/shared/validation.ts` 放简单纯函数；`src/server.ts` 组装应用。

调用方向：路由/模板 → 服务（业务规则、事务）→ SQL 查询 → SQLite。校验纯函数不依赖 Express、模板或数据库。无需为每个表增加接口和适配器层。班级服务只检查学生关联，学生删除和成绩删除在同一事务完成。

## 数据模型

所有表使用整数自增主键；外键使用 ID，学号和名称可编辑，不作为关联键。时间字段 `created_at`、`updated_at` 存 UTC ISO 字符串；更新由服务统一设置。

| 表 | 字段与约束 |
| --- | --- |
| classes | id；name TEXT NOT NULL UNIQUE（1–50 字符）；时间字段 |
| students | id；student_no TEXT NOT NULL UNIQUE；name TEXT NOT NULL；class_id INTEGER NULL REFERENCES classes(id) ON DELETE RESTRICT；时间字段 |
| subjects | id；name TEXT NOT NULL UNIQUE（1–50 字符）；时间字段 |
| scores | id；student_id NOT NULL REFERENCES students(id) ON DELETE CASCADE；subject_id NOT NULL REFERENCES subjects(id) ON DELETE RESTRICT；score_tenths INTEGER NOT NULL CHECK(typeof(score_tenths)='integer' AND score_tenths BETWEEN 0 AND 1000)；UNIQUE(student_id,subject_id)；时间字段 |

关系：班级 1→N 学生（学生可暂未分班）；学生 1→N 成绩；科目 1→N 成绩。首版每学生每科只有一条当前成绩，不包含学期、考试或历史成绩；若要多次考试，新增 exams 并把唯一约束改为学生+科目+考试，不复用名称伪装考试。

索引：`students(class_id)`、`scores(subject_id)`；成绩复合唯一索引同时服务按学生查询。班级人数实时统计，避免存冗余计数。

## 校验和关联操作

- 学号先 trim、转大写，允许 ASCII 字母数字及连字符，长度 1–32；作为字符串保留前导零。数据库唯一约束兜底；编辑排除当前学生，冲突显示“学号已存在”。
- 姓名 trim 后 1–50 字符；不强制中文，不收集身份证、手机号等额外信息。班级和科目名称 trim 后 1–50 字符，规范化后的同名拒绝；空白字段拒绝。
- class_id 可空；非空必须存在。学生分班仅改 class_id，不影响原成绩。未分班在列表及筛选中明确显示。
- 成绩必填，接受 0–100（含边界）、至多一位小数；拒绝空值、负数、101、NaN、Infinity、科学计数法及超过一位小数。先校验十进制文本再转换为整数十分值，显示时除以 10，不使用浮点范围近似。新建重复学生+科目返回可理解错误，引导编辑原记录。
- 删除有关联学生的班级一律拒绝，提示“该班级有 N 名学生，请先转班或取消分班”；不级联删除学生。空班级可确认后删除；检查与删除在事务内，外键兜底。
- 删除学生前明确提示将同步删除其成绩，确认后在事务内执行；取消不产生写入。科目有成绩则禁止删除；可改名。删除成功与错误均中文反馈。
- 前端 required/min/max 仅帮助输入，服务端重复检查；数据库 NOT NULL/UNIQUE/CHECK/FK 是最后防线。所有 SQL 参数化，EJS 默认转义输出，不使用未转义用户内容。

## 页面与请求约定

学生、班级、科目、成绩独立列表与表单；学生详情可集中看成绩。导航建议“学生档案 / 班级管理 / 成绩管理（含科目）”。设计师可调整布局，保持上述字段、关联和反馈一致。

读页面使用 GET；新增、编辑、删除使用 POST，禁止 GET 修改数据。成功写入以 303 重定向到列表或详情，避免刷新重复提交；校验失败保留输入并显示字段错误（422），找不到记录为 404，唯一键或关联冲突为 409。

学生 GET 查询参数 `q` 匹配姓名或学号的包含搜索（学号查询同样转大写）；`classId` 为班级 ID 或 `unassigned`。关键字与班级条件取 AND。成绩页可按学生关键字、班级及科目过滤。搜索 trim，最长 100 字符；SQL LIKE 的 `%`、`_` 按普通字符转义。列表按固定 ID 顺序分页（默认 20、最大 100），筛选与跳页保留条件，空结果提供中文提示。

## 持久化、初始化与故障行为

数据库路径默认仓库根目录 `data/student-management.sqlite`，基于项目根定位而非调用者当前目录；允许 `DATABASE_PATH` 覆盖。启动创建目录，启用 `PRAGMA foreign_keys=ON` 和适当 busy_timeout（如 5000ms）；迁移表记录版本，迁移失败停止启动。数据库文件及 journal/WAL 文件加入 .gitignore，不提交个人本地数据。

建议脚本契约（开发阶段实现并实测）：`npm ci`、`npm run db:migrate`、`npm run db:seed`、`npm run dev`、`npm run build`、`npm start`、`npm test`。启动自动迁移亦可，但 README 必须与实现一致。种子采用事务、固定合成记录及“仅空数据库可初始化”检查；重复运行不覆盖用户录入，不默认清库。首次网页显示空状态和初始化说明，不在每次启动自动补回被删除的样例。

样例建议：2 个虚构班级、6 名“演示学生01”等合成学生（含 1 名未分班）、3 科、含 0/100/小数的成绩。重启及刷新保持数据；数据库写入失败不得显示成功。默认监听 `127.0.0.1`，保持同源表单并加 CSRF 防护，不开放网络。无需登录、复杂角色或真实资料导入。

备份：停止服务后复制数据库；恢复：停止服务后替换同版本数据库再启动。README 说明这是本地演示数据文件，不承诺跨机器自动同步；重置须显式确认或指定独立数据库，不把删除文件放在普通启动脚本中。
